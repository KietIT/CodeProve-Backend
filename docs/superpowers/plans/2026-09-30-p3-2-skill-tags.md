# P3.2 Skill Tags Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Every exercise carries 1–3 reviewed skill tags from a fixed taxonomy, so P3.3 can keep an Elo rating per skill.

**Architecture:** The taxonomy (18 keys after review with vi/en labels) lives in code. Tags live in each content file as a `skills` block with its own review, like the `debug` block (P2.2), so tagging does not un-approve the file. Content sync writes approved tags to `exercises.skills`; the exercise API returns them with labels.

**Tech Stack:** pydantic v2, SQLAlchemy async, Alembic, pytest.

---

### Task 1: Taxonomy and content schema

**Files:**
- Create: `app/features/content/skills.py` (`TAXONOMY`, `MAX_SKILLS = 3`)
- Modify: `app/features/content/schema.py`: `ContentSkills(tags, review)`, where `tags` has 1–3 entries, each a known key, no repeats. `ExerciseContent.skills: ContentSkills | None`.
- Test: `tests/test_content_skills.py`: both labels exist; bad tags are rejected; every real content file has a valid block.

### Task 2: Storage and sync

**Files:**
- Create: `alembic/versions/a1c3e5f7b9d2_exercise_skills.py`: `exercises.skills` JSON, `server_default '[]'`, revises `e7a9c1d3f5b8`.
- Modify: `app/models/exercise.py` (the `skills` column).
- Modify: `app/features/content/sync.py`:
  - Write the tags only when `skills.review` is approved. A draft leaves the stored tags as they are.
  - The dry run prints `skills ... approved by X: written` or `... are a draft: not written`.
- Test: a draft is not written, an approved block is, and a later draft keeps the stored tags.

### Task 3: API

**Files:**
- Modify: `app/features/exercises/service.py`: `skill_labels(ex)` returns `[{key, vi, en}]` and drops keys no longer in the taxonomy.
- Modify: `app/schemas/exercise.py`: `SkillTag`; `ExerciseSummary.skills` (list and detail).
- Test: both endpoints return the labels and drop the unknown key.

### Task 4: Content and review sheet

- Add a draft `skills` block (author `claude`) to all 30 files.
- Write `docs/calibration/skill-tags-can-duyet.md` (taxonomy, per-exercise tags, review steps).
- The team reviews the sheet. The reviewer's name then goes into each `skills.review`. Only then does the owner run `content.sync --apply`.

**Out of scope:**
- Showing tags in the UI. That comes with P3.3/P3.4, when there is a skill profile to show.
