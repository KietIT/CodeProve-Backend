# P2.3 Tests Tab (student-written tests) — Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** The student writes their own tests in a "Tests" tab (category, input, expected value, one line "why"). The Testing axis then measures testing skill: are the tests right (valid against the reference), do they cover the categories, do they catch real bugs (mutation score on the exercise's validated mutants), plus, as decided, whether the solution passes the hidden suite.

**Architecture:** Student tests are saved server-side (`TESTS_SAVED` events, latest wins). A live check runs one test against the **reference solution** and answers only *valid / wrong expected / error*, never the reference's output. At submit the server writes one `STUDENT_TESTS` event: the final tests, their validity, and which mutants each valid test kills. `rubric.testing` uses the new indicators only when that event exists, so old sessions keep their scores (decision 6). Inputs are Python expressions restricted by an AST allow-list, because a free expression run against the reference could leak it bit by bit through the valid/invalid answer (e.g. `1 if 'x' in inspect.getsource(f) else 0`).

**Tech Stack:** FastAPI, SQLAlchemy async, pydantic v2, pytest; `ast`; the existing sandbox `run_tests` (one subprocess per code version, all cases at once) and rate limiter.

**Design:** `docs/superpowers/specs/2026-09-29-p2-design.md` (P2.3; decisions 2 = A, 3 = A of 2026-09-30).

---

## Facts this plan relies on (checked 2026-09-30)

- Every exercise has 3–5 validated mutants (`exercise_mutants`, each killed by ≥ 1 reference test, not by all) and a synced `reference_solution`.
- A test is an expression evaluated after the code, compared by `repr` with the expected string (sandbox `run_tests`).
- **12/30 exercises** (CP-002, 012, 103, 104, 106, 108, 109, 110, 201, 206, 207, 208) have reference tests that need `globals()`, `__import__`, dunder attributes or `open`: threads, files, linked-list nodes, DB fakes. Those are exactly the constructs the allow-list must refuse.

## Rules proposed in this plan

- **Input allow-list** (checked with `ast` before anything runs): literals and containers, arithmetic/comparison/boolean operators, subscripts, comprehensions, lambdas, calls; names = the names the reference module defines at top level (`def`, `class`, assignments) + a small set of safe builtins (`len`, `sorted`, `list`, `dict`, `set`, `tuple`, `range`, `str`, `int`, `float`, `bool`, `min`, `max`, `sum`, `abs`, `any`, `all`, `enumerate`, `zip`, `reversed`, `isinstance`); attributes only non-underscore names. Refused: `import`, dunders, `globals/locals/vars/getattr/setattr/eval/exec/open/compile/__import__/inspect`. Max 300 chars.
- **Tab enabled per exercise** only where the tests can be written under the allow-list: an exercise gets the tab when at least half of its own reference tests pass the allow-list (computed and checked by the content validator, stored as `exercises.student_tests` bool). Estimate from a pattern scan: about 21 exercises get it; about 9 do not (CP-002, 012, 103, 106, 109, 201, 206, 207, 208, where most tests need privileged constructs), and there Testing = the correctness indicator only, as today. CP-104, 108 and 110 need them in only a few tests and keep the tab. Task 1 computes the exact list with the real allow-list.
- **Live check** (`valid` / `wrong_expected` / `error` + for `error` only the exception type or the allow-list reason): shares the sandbox rate limit (20/min); each check is logged (`TEST_CHECK`) so abuse is visible.
- **Expected values** are normalised (`ast.literal_eval` then `repr`), so `[0,1]` and `[0, 1]` match.
- **Limits:** at most 10 tests per attempt; junior/senior need **3 valid tests** for full marks on "valid tests".
- **Levels (Testing v3):**

| Indicator | 3 | 2 | 1 | 0 |
|---|---|---|---|---|
| Valid tests (valid / max(3, written)) | 100% | ≥ 75% | ≥ 50% | < 50% or none |
| Category coverage (distinct categories among valid tests vs the exercise's) | all | all but one | one | none |
| Mutation score (mutants killed by the valid tests) | all | ≥ 2/3 | ≥ 1/3 | < 1/3 |
| Correctness (decision 2 = A; the P1.4 `testing` indicator: hidden suite) | all pass | visible pass, hidden fail | visible fail | never ran / mostly failing |

  Axis = mean of the applicable indicators. **Fresher without tests:** only Correctness applies (the tab is optional there, decision 3 = A). **Junior/senior without tests:** the three test indicators are 0.
- **After submit** the report shows each test (valid or not), categories covered, the mutation score, and for each surviving mutant its `note_vi/en` (the kind of bug the tests missed), never the mutant code.

### Task 1: Input allow-list and per-exercise enablement

**Files:** Create `app/features/student_tests/safety.py`; modify `app/features/content/validate.py`, `schema.py` (report the computed flag), `app/models/exercise.py` + migration (`exercises.student_tests` bool, default false), `app/features/content/sync.py`; tests `tests/test_student_tests_safety.py`, content tests.

- `check_input(expr, allowed_names) -> str | None` (None = allowed, else the reason); `module_names(reference) -> set[str]`.
- Validator: computes the share of the exercise's reference tests the allow-list accepts; sync writes `student_tests = share ≥ 0.5`. Dry run prints it per exercise. The P2.3 report lists which exercises got the tab.
- Tests: accepted (calls, lambdas on class exercises, comprehensions); refused (every forbidden construct, dunders, over-long, syntax errors); the enablement count on the real content files.

Commit `feat(student-tests): input allow-list and per-exercise enablement`.

### Task 2: Save, check and run student tests

**Files:** Create `app/features/student_tests/service.py`, `router` endpoints under `/api/attempts/{id}/tests`; modify `app/schemas/attempt.py` (`AttemptState.tests`), `attempts/service.SERVER_EVENT_TYPES` (add `TESTS_SAVED`, `TEST_CHECK`, `STUDENT_TESTS`); tests `tests/test_student_tests_api.py`.

- `PUT /tests` body `{tests: [{category, input, expected, why}]}` (≤ 10) → saves (`TESTS_SAVED`, latest wins); 409 after submit; 400 when the exercise has no tab.
- `POST /tests/check` body one test → `{status: "valid" | "wrong_expected" | "error", reason?}` against the reference; never an output value. Rate-limited with the sandbox limit.
- `POST /tests/run` → runs the saved tests against the student's **current code** and returns pass/fail and actual values (their own code: no leak).
- `AttemptState.tests: {enabled, required, tests}` so a reload restores the tab.

Commit `feat(student-tests): save, check against the reference, run on own code`.

### Task 3: Evaluate at submit

**Files:** Create `app/features/student_tests/evaluate.py`; modify `app/features/attempts/router.py` (submit); tests.

- At submit on an exercise with the tab: validity of every saved test against the reference (one sandbox run), then the valid tests against each mutant (one run per mutant) → `STUDENT_TESTS {tests: [{…, valid}], categories, mutants: [{id, bug_type, killed}], score}` (written even with no tests, so "no tests" is observable).
- Tests: validity, kill matrix, empty set, a test that errors on the reference is invalid, time budget (≤ 1 + mutants sandbox runs).

Commit `feat(student-tests): validity and mutation score at submit`.

## Decisions for Kiệt

1. **Allow-list + tab only where tests fit it** (≈ 21 exercises), rather than free Python everywhere (leaks the reference through the check) or writing per-exercise test helpers for the ≈ 9 others now (content work; possible later).
2. **Fresher without tests: Testing = correctness only** (reconciles decisions 2 = A and 3 = A: the design said "N/A", but with correctness as a Testing indicator the axis can still be scored).
3. **Junior/senior: 3 valid tests** for full marks on "valid tests"; at most 10 tests.
4. **Live check answers only valid / wrong expected / error**, rate-limited, never the output.
